seam       content_boundary_lab.trust.content_identity
twin       labs.f03_declared_identity.vulnerable.content_identity
scenario   a marker file is declared with the SHA-256 of a clean file whose verdict is already cached

== REFERENCE

       -> 200 SCAN_PASSED, scanner calls: 1
  2. a marker file with an allowed signature is delivered, declared with the CLEAN file's SHA-256 and its own size
       -> upload accepted, 935 bytes, declared sha256 b75f1f348b4f…
  3. the vendor seals it
       -> 422 REJECTED (checksum_mismatch)
  4. scanner calls made for that seal
       -> 0
  5. what the server holds as the sealed digest of the delivery
       -> 1629f3591a5f… (the digest of the stored bytes)

  7. audit events about that delivery
       -> delivery.initiated, delivery.upload_started, delivery.uploaded, delivery.seal_started, delivery.rejected (checksum_mismatch)
  8. the coordinator inspects it
       -> 200 REJECTED
