# Claims register

Every claim the README and the documentation make about what the reference implementation does, each with the tests that
show it. A claim without a test is deleted, not softened, and `tests/test_docs.py` fails if a claim here cites a test that
does not exist. A passing test shows that the corrected code blocks the case it exercises **under the assumptions in
[threat-model.md](threat-model.md)**; it does not show that nothing else is wrong. Tests are cited by file and function.

The threats these claims answer are in [threat-model.md](threat-model.md) (the TM numbers below); how the pieces fit is in
[architecture.md](architecture.md).

## 2. Claims this repository does not make

None of these is claimed anywhere, and each is stated so that its absence is not read as an omission.

- That the application, or any part of it, is free of flaws, or is fit for any production use. Passing tests show that a case
  is blocked under stated assumptions, not that other cases do not exist.
- Conformance to any standard or any ASVS level. Findings are mapped to specific requirements in
  [references.md](references.md) and no level is claimed.
- That the scanner detects malware, or that `no_detection` says anything about a file other than that the synthetic scanner
  found nothing.
- That the audit trail is tamper-evident, that the database cannot be changed by whoever can write the file, or that the
  trusted root is verified again after promotion.
- That a SQLite transaction and a filesystem operation are one atomic act; where a file operation sits inside a
  transaction the document says what a failure leaves behind and what the code takes back.
- Durability across a power failure, or any behaviour on a platform other than the one in the lock (CPython 3.13.7,
  macOS arm64). In particular no Linux run has been made, and nothing here is cross-platform verified.
- That any human or otherwise independent reviewer has read the code or these claims. The reviews in
  [review/](review/m4-findings.md) were made by the model that wrote the code and by sub-agents of the same model; the
  human reviewer of M0 D10 is pending.
- That the continuous-integration workflow has run on any host. It is written and its text is checked locally (C-30).
- That the choice of licence, its holder or the project's name has been confirmed or cleared; they are defaults awaiting the
  owner ([publication.md](publication.md)).
- That a stranded `SEALING` delivery recovers (it is listed and left as it is), that reconciliation may be scheduled, that
  the exclusion between the lab's processes holds against a program that does not ask for it, or that the path-routing
  answers for malformed URLs are uniform (see the limitations in [architecture.md](architecture.md)).
- That the local server run establishes readiness for any use other than the one it was: one server, one machine,
  `127.0.0.1`, synthetic data, a handful of requests. There is no TLS, no load or abuse testing, and nothing is said about
  how `uvicorn` treats a malformed or hostile request beyond the cases the real-server tests name.
- Anything about cloud services, pre-signed URLs, federation or CSAP conformance; those are analogies only.
- That any seeded variant describes a real system, or that the capability F-04 assumes (something other than the application
  writing quarantine after the seal) exists in any deployment: that finding is conditional on it. F-03's scenario ends at
  `SCAN_PASSED` and claims nothing about the trusted store, and F-06's window here is at most the ten minutes a reference token
  may live (what a revoked coordinator makes in that window is not bounded by it: C-26).
- That a vendor's file name, extension included, matches what the file is, or that a downloaded file is harmless to open on the
  recipient's machine: the application serves every download as an attachment of unknown type that a browser is told not to
  interpret, and says nothing about what the recipient's system will do with the saved file (TM-40).
- That a mistyped storage root is detected: the lab cannot tell a wrong quarantine directory from one whose files have gone, and
  treats it as the latter (TM-41).
- That the reference has no other flaw of the same four kinds. The remediation matrices (claim C-28) probe the four
  functions that were seeded, with the partial fixes that fail them; they do not probe every other function of the
  reference for the same kinds of flaw.
- Any performance, availability or incident-reduction figure.
